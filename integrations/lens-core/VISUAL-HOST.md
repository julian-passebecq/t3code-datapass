# DataPass Visual Host trial

The existing `/datapass` module mounts a Repository Atlas in a project-aware
T3 shell. It imports a bounded Lens snapshot explicitly and uses a DiagramCloud
package distribution. Generic T3 auth, orchestrator, providers, worktree internals
and native HTML renderer are unchanged. No Lens algorithms or Agent collectors
are copied into T3. The injected Core adapter returns the Atlas alongside its
existing intelligence envelope.

Selection is a bounded ID message from the exact sandbox iframe. The DataPass
module resolves that ID against the validated payload, displays facts and
relationships, matches exact checkouts to existing T3 projects/threads, opens
review links, and offers an explicit editor context link. Impact and Evolution
switch renderer views of the same payload. No Git mutations run from a diagram.

The native `html_render` mechanism accepts a self-contained portable page, stores
it as a thread attachment, and uses opaque-origin frames with theme messages and
bounded size notifications. `html_preview` measures a page first. The module can
download the exact native tool request; submission remains explicit. Native
thread HTML currently offers theme, size and HTTP(S) link callbacks, not arbitrary
Git/Agent action callbacks. Rich host navigation therefore lives in the DataPass
module, while portable thread pages retain selection and factual inspectors.

The persistent project entry reuses `/datapass`, with explicit keep/restore of one
bounded snapshot on this device. No upstream navigation fork or automatic scan
is needed. Remote authenticated T3 access is distinct from public publication.

Package distributions under `src/datapass/generated/diagram-core` are built from
DiagramCloud's canonical `packages/development-core`, with owner SHA metadata and
licenses. Regenerate them from that package; never edit the generated renderer.
The future `datapass.visual-app/1` idea stays a seam, not an implemented SDK.
